### Open-source projects

#### [Voidbreaker](https://github.com/chuthuong13492/void_breaker): a roguelite shooter in pure Flutter, with no game engine
`Flutter` `Dart` `CustomPainter` `Kotlin` `Swift`

A top-down dungeon shooter for iOS and Android. Every sprite and sound is generated by code, and the game has only two package dependencies.
- The whole scene renders through one `CustomPainter` with `drawRawAtlas`. Draw calls stay flat as sprite count grows: 4 calls whether 74 or 2,751 sprites are on screen.
- The simulation doesn't import Flutter at all. It's deterministic (same seed, same run hash), and a full run can be played inside a plain Dart test.
- It has 690 tests, including architecture tests that fail the build when a layer boundary is crossed.
- The audio engine uses hand-written `AVAudioEngine` / `AudioTrack` platform channels instead of a plugin.
- The performance figures are measured on a desktop and an Android emulator and haven't been validated on physical devices yet; the repo says so explicitly.

#### [dart_pair_mcp](https://github.com/chuthuong13492/dart_pair_mcp): AST-based MCP server for Dart and Flutter engineering
`Dart` `package:analyzer` `MCP`

A Model Context Protocol server that gives AI coding agents typed tools for refactoring, code generation and architecture enforcement. It's designed to run alongside the official `dart mcp-server`.
- It reads and edits code only through the analyzer AST, never regex. Supported refactors include rename, extract widget/method, and move-file with import rewriting.
- It detects Clean Architecture boundary violations and framework misuse (Bloc, Riverpod, Provider) from declarative YAML rule packs.
- Every mutating tool is dry-run by default. The server itself uses a ports-and-adapters design, with a plugin seam and CI.

#### [Fine Mobile](https://github.com/chuthuong13492/Fine_Mobile): Flutter food-ordering app
`Flutter` `Provider` `Dio` `Firebase`

A customer app for ordering food to pickup stations in time slots. It supports group ("party") orders and a wallet top-up.
- It's split into MVVM layers: View, ViewModel, and DAO/DTO models.
- It includes phone OTP and Google sign-in, FCM push notifications, dynamic links, and geolocation.
- I wrote it solo, across 105 commits.

#### [AutoTrader Web](https://github.com/chuthuong13492/autotrader): vehicle marketplace frontend
`React 19` `TypeScript` `TanStack Query / Router` `Redux Toolkit` `Zod`

A search and listing UI with filtering, pagination and detail views. It's organised as feature modules.
- Server state lives in TanStack Query and client state in Redux Toolkit / Zustand, kept deliberately separate.
- It has typed routing, Zod-validated forms, a Jest test setup, and dead-code checks with Knip.
